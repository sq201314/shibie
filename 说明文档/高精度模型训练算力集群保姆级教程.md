# 高精度模型训练 · 算力集群从零搭建保姆级教程

> **核心目标**：从裸机开始，搭建一套多机分布式训练算力集群，并在上面跑出**高精度、高质量**的 YOLO 目标检测模型。
> **适用硬件**：2 台及以上 × (NVIDIA RTX 3060 12GB)
> **操作系统**：Ubuntu 22.04.5 LTS
> **CUDA 版本**：CUDA 12.6
> **训练框架**：PyTorch + Ultralytics（YOLO），DDP 数据并行
> **文档日期**：2026-08-24

> **本文档分两条线**：
> 1. **算力线（第一~八章）**：从零把集群搭起来，让多张 GPU 能协同工作。
> 2. **精度线（第九~十三章）**：在集群上把模型精度做上去——数据质量、训练技巧、监控评估、调优路线。

### 0.4 协同训练原理（先理解再动手）

```
一个模型的参数（权重）= 在每张卡上各保存一份完整副本

           ┌─────────────┐
           │  全局 Batch  │  比如 12 张图片
           └──────┬──────┘
                  │ 切分
            ┌─────┴─────┐
            ▼           ▼
       ┌─────────┐ ┌─────────┐
       │ GPU 0   │ │ GPU 1   │
       │ 6 张    │ │ 6 张    │
       │         │ │         │
       │ 完整模型│ │ 完整模型│
       │ 前向传播│ │ 前向传播│
       │ 反向传播│ │ 反向传播│
       └────┬────┘ └────┬────┘
            │           │
            ▼           ▼
          梯度0       梯度1
            │           │
            └─────┬─────┘
                  ▼
            AllReduce 同步
           (所有梯度取平均)
                  │
                  ▼
            两份模型参数
            同时更新 → 保持一致
```

**一句话总结**：每张卡用不同的数据子集做前向+反向，然后 AllReduce 平均梯度，所有卡的模型始终同步。

> **分布式与精度的关系**（重要）：多卡训练用「更大的全局 Batch」换「更快的训练」，但**大 Batch 会损害收敛质量**。因此本教程在第十章专门用「线性缩放学习率 + SyncBN + 余弦退火」等手段把精度补回来——这是"算力集群 + 高精度"能同时成立的关键。

## 第一章：基础系统配置

> **以下所有步骤，两台机器都要做，除非特别说明。**

### 1.1 确认系统版本

```bash
cat /etc/os-release
```

确认输出包含 `Ubuntu 22.04.5 LTS`。

### 1.2 更新系统

```bash
sudo apt update
sudo apt upgrade -y
sudo reboot
```

### 1.3 安装基础工具

```bash
sudo apt install -y \
  build-essential \
  cmake \
  git \
  wget \
  curl \
  vim \
  net-tools \
  htop \
  tmux \
  chrony \
  nfs-common \
  software-properties-common \
  iperf3
```

每个工具的作用：

| 工具 | 用途 |
|------|------|
| build-essential | 编译 C/C++ 代码 |
| git | 版本管理 |
| wget/curl | 下载文件 |
| vim | 文本编辑 |
| htop | 进程监控 |
| tmux | 终端复用（保护训练不被 SSH 断开中断） |
| chrony | 时间同步 |
| nfs-common | NFS 客户端 |
| iperf3 | 网络带宽测试 |

### 1.4 时间同步

分布式训练对时间敏感，必须保证所有机器时钟一致：

```bash
sudo systemctl enable chrony
sudo systemctl start chrony
chronyc tracking
```

看到 `System time : 0.xxxxxx seconds fast` 就正常。

### 1.5 设置主机名

```bash
# 第一台（Master）
sudo hostnamectl set-hostname node1

# 第二台（Worker）
sudo hostnamectl set-hostname node2

# 如果有第三台
sudo hostnamectl set-hostname node3
```

### 1.6 配置静态 IP

先确认网卡名称：

```bash
ip a
```

找到插网线的接口名（比如 `enp4s0`、`eno1`、`eth0`），记住这个名字。

编辑 Netplan：

```bash
sudo nano /etc/netplan/01-installer-config.yaml
```

**第一台（node1）配置：**

```yaml
network:
  version: 2
  ethernets:
    enp4s0:                    # ← 替换为你的实际网卡名
      dhcp4: no
      addresses:
        - 192.168.1.100/24
      routes:
        - to: default
          via: 192.168.1.1    # ← 替换为你的网关地址
      nameservers:
        addresses: [8.8.8.8, 114.114.114.114]
```

**第二台（node2）配置：**

```yaml
network:
  version: 2
  ethernets:
    enp4s0:                    # ← 替换为你的实际网卡名
      dhcp4: no
      addresses:
        - 192.168.1.101/24
      routes:
        - to: default
          via: 192.168.1.1    # ← 替换为你的网关地址
      nameservers:
        addresses: [8.8.8.8, 114.114.114.114]
```

应用配置：

```bash
sudo netplan apply
```

验证：

```bash
ip addr show enp4s0
ping -c 3 192.168.1.1       # ping 网关
```

### 1.7 配置 hosts 文件

两台机器都做，内容完全一样：

```bash
sudo bash -c 'cat > /etc/hosts << EOF
127.0.0.1   localhost
192.168.1.100  node1
192.168.1.101  node2
EOF'
```

如果有第三台，追加 `192.168.1.102  node3`。

### 1.8 关闭防火墙

```bash
sudo ufw disable
```

> 生产环境应配置精确的防火墙规则，这里为简化操作直接关闭。

### 1.9 互相 ping 测试

```bash
# 在 node1 上
ping -c 3 node2

# 在 node2 上
ping -c 3 node1
```

两台都能 ping 通才能继续。

### 1.10 创建数据盘挂载点

如果有独立的数据盘（推荐），格式化并挂载：

```bash
# 查看磁盘
lsblk

# 假设数据盘是 /dev/sdb
sudo mkfs.ext4 /dev/sdb
sudo mkdir -p /data
sudo mount /dev/sdb /data

# 开机自动挂载
echo '/dev/sdb /data ext4 defaults 0 2' | sudo tee -a /etc/fstab

# 设置权限
sudo chown -R $(whoami):$(whoami) /data
```

## 第二章：SSH 免密互信

**目标**：任何一台机器可以无密码 SSH 到其他任何一台。

### 2.1 两台机器创建相同用户名

如果已有相同用户名则跳过。

```bash
# 两台都做
sudo adduser gpucluster
sudo usermod -aG sudo gpucluster
```

> 后续所有操作都以这个用户进行。下面用 `$(whoami)` 代替实际用户名。

### 2.2 在 node1 上生成密钥

```bash
ssh-keygen -t ed25519 -C "cluster-key"
# 一路回车，不设密码
```

### 2.3 把公钥分发到所有节点（包括自己）

```bash
ssh-copy-id $(whoami)@node1
ssh-copy-id $(whoami)@node2
```

每台都要输入一次密码。

### 2.4 在 node2 上也做同样的事

```bash
ssh-keygen -t ed25519 -C "cluster-key" -N ""
ssh-copy-id $(whoami)@node1
ssh-copy-id $(whoami)@node2
```

### 2.5 验证免密登录

```bash
# 从 node1
ssh $(whoami)@node2 "hostname && whoami"
# 输出: node2 / 你的用户名（不需要密码）

# 从 node2
ssh $(whoami)@node1 "hostname && whoami"
# 输出: node1 / 你的用户名（不需要密码）
```

### 2.6 优化 SSH 配置（可选但推荐）

编辑 `/etc/ssh/sshd_config`，确保以下配置：

```bash
sudo nano /etc/ssh/sshd_config
```

```
ClientAliveInterval 60
ClientAliveCountMax 3
TCPKeepAlive yes
```

重启 SSH：

```bash
sudo systemctl restart sshd
```

## 第三章：NVIDIA 驱动安装

### 3.1 禁用 Nouveau 开源驱动

```bash
# 检查 nouveau 是否加载
lsmod | grep nouveau
```

如果有输出，需要禁用：

```bash
sudo bash -c 'cat > /etc/modprobe.d/blacklist-nouveau.conf << EOF
blacklist nouveau
options nouveau modeset=0
EOF'

sudo update-initramfs -u
sudo reboot
```

重启后确认：

```bash
lsmod | grep nouveau
# 应该没有输出了
```

### 3.2 安装 NVIDIA 驱动

```bash
# 查看推荐驱动版本
ubuntu-drivers devices
```

输出类似：

```
vendor   : NVIDIA Corporation
model    : GA106 [GeForce RTX 3060]
driver   : nvidia-driver-535 - distro non-free recommended
driver   : nvidia-driver-550 - third-party non-free
```

安装推荐版本（建议安装 550 或更高版本以更好支持 CUDA 12.6）：

```bash
# 方式一：安装推荐版本
sudo ubuntu-drivers autoinstall

# 方式二：指定版本安装（推荐 550+）
sudo apt install -y nvidia-driver-550

sudo reboot
```

### 3.3 验证驱动安装

```bash
nvidia-smi
```

应看到类似输出：

```
+-----------------------------------------------------------------------------------------+
| NVIDIA-SMI 550.xx.xx              Driver Version: 550.xx.xx      CUDA Version: 12.6     |
+-----------------------------------------+------------------------+----------------------+
| GPU  Name                 Persistence-M | Bus-Id          Disp.A | Volatile Uncorr. ECC |
| Fan  Temp   Perf          Pwr:Usage/Cap |           Memory-Usage | GPU-Util  Compute M. |
|=========================================+========================+======================|
|   0  NVIDIA GeForce RTX 3060        Off |   00000000:01:00.0  On |                  N/A |
|  0%   48C    P8             22W /  170W |     142MiB /  12288MiB |      4%      Default |
+-----------------------------------------+------------------------+----------------------+
```

> **重要**：`nvidia-smi` 显示的 `CUDA Version: 12.6` 是驱动支持的最高 CUDA 版本，不是你实际安装的 CUDA Toolkit 版本。这没关系，下一步会安装 CUDA Toolkit 12.6。

### 3.4 开启 GPU 持久化模式（可选，推荐）

持久化模式可以减少 GPU 初始化延迟：

```bash
sudo nvidia-smi -pm 1
```

永久生效：

```bash
sudo bash -c 'cat > /etc/systemd/system/nvidia-persistenced.service << EOF
[Unit]
Description=NVIDIA Persistence Daemon
After=syslog.target

[Service]
Type=forking
ExecStart=/usr/bin/nvidia-persistenced --user $(whoami)
ExecStopPost=/bin/rm -rf /var/run/nvidia-persistenced
Restart=always

[Install]
WantedBy=multi-user.target
EOF'

sudo systemctl enable nvidia-persistenced
sudo systemctl start nvidia-persistenced
```

## 第四章：CUDA Toolkit 12.6 安装


```bash
cat >> ~/.bashrc << 'EOF'

# CUDA 12.6
export CUDA_HOME=/usr/local/cuda-12.6

export LD_LIBRARY_PATH=$CUDA_HOME/lib64:$LD_LIBRARY_PATH

source ~/.bashrc
```

### 4.4 验证 CUDA 安装

```bash
nvcc --version
```

应显示：

```
nvcc: NVIDIA (R) Cuda compiler driver
Cuda compilation tools, release 12.6, V12.6.xxx
```

### 4.5 安装 cuDNN

```bash
sudo apt install -y libcudnn8 libcudnn8-dev
```

验证：

```bash
cat /usr/include/cudnn_version.h | grep CUDNN_MAJOR -A 2
```

## 第五章：NFS 共享存储

**目的**：让所有机器看到同一份数据和代码，不用每台复制一份。

### 5.1 Master（node1）上安装 NFS Server

```bash
sudo apt install -y nfs-kernel-server
```

### 5.2 创建共享目录结构

```bash
sudo mkdir -p /data/shared/{datasets,checkpoints,code,logs,configs,envs}
sudo chown -R $(whoami):$(whoami) /data/shared
chmod -R 775 /data/shared
```

目录结构说明：

```
/data/shared/
├── datasets/       ← 数据集存放
├── checkpoints/    ← 模型 checkpoint
├── code/           ← 训练代码
├── logs/           ← 训练日志
├── configs/        ← 配置文件
└── envs/           ← 共享 conda 环境
```

### 5.3 配置 NFS 导出

```bash
echo "/data/shared 192.168.1.0/24(rw,sync,no_subtree_check,no_root_squash)" | \
  sudo tee /etc/exports

sudo exportfs -ra
sudo systemctl restart nfs-kernel-server
sudo systemctl enable nfs-kernel-server
```

验证导出：

```bash
sudo exportfs -v
```

应看到 `/data/shared` 的导出信息。

### 5.4 Worker（node2）上挂载 NFS

```bash
sudo apt install -y nfs-common
sudo mkdir -p /data/shared
sudo mount node1:/data/shared /data/shared
```

验证：

```bash
ls /data/shared/
# 应该看到 datasets checkpoints code logs configs envs

df -h /data/shared
```

### 5.5 设置开机自动挂载

```bash
echo 'node1:/data/shared /data/shared nfs defaults,_netdev 0 0' | \
  sudo tee -a /etc/fstab

# 测试 fstab 是否正确
sudo umount /data/shared
sudo mount -a
ls /data/shared/
```

### 5.6 验证读写

```bash
# 在 node1 上写入
echo "hello from $(hostname)" > /data/shared/test.txt

# 在 node2 上读取
cat /data/shared/test.txt
# 应该输出: hello from node1

# 清理
rm /data/shared/test.txt
```

## 第六章：共享 Conda 环境 + PyTorch

> **关键决策**：将 conda 环境装到 NFS 共享路径 `/data/shared/envs/train`，所有机器都能用，避免重复安装。

### 6.1 安装 Miniconda（两台都做）

```bash
cd /tmp
wget https://repo.anaconda.com/miniconda/Miniconda3-latest-Linux-x86_64.sh
bash Miniconda3-latest-Linux-x86_64.sh -b -p $HOME/miniconda3

eval "$($HOME/miniconda3/bin/conda shell.bash hook)"
conda init bash
source ~/.bashrc
```

验证：

```bash
conda --version
```

### 6.2 创建共享训练环境（只需在 node1 上做一次）

```bash
# 创建环境
conda create --prefix /data/shared/envs/train python=3.10 -y
conda activate /data/shared/envs/train

# 安装 PyTorch（CUDA 12.6 版本）
# 注意：torchaudio 没有 cu126 的 wheel，做视觉训练不需要它，跳过
pip install torch torchvision \
  --index-url https://download.pytorch.org/whl/cu126

# 安装 YOLO 训练所需的库
pip install ultralytics

# 安装常用库
pip install timm transformers opencv-python-headless \
  tqdm matplotlib scipy einops
```

### 6.3 验证 PyTorch + CUDA

两台都验证：

```bash
# 在 node1 上
python3 -c "
import torch
print(f'PyTorch 版本  : {torch.__version__}')
print(f'CUDA 可用     : {torch.cuda.is_available()}')
print(f'CUDA 版本     : {torch.version.cuda}')
print(f'GPU 名称      : {torch.cuda.get_device_name(0)}')
print(f'GPU 显存      : {torch.cuda.get_device_properties(0).total_memory / 1024**3:.1f} GB')
print(f'NCCL 版本     : {torch.cuda.nccl.version()}')
"

# 在 node2 上远程验证
ssh $(whoami)@node2 "source ~/miniconda3/etc/profile.d/conda.sh && \
conda activate /data/shared/envs/train && \
python3 -c \"
import torch
print(f'PyTorch: {torch.__version__}')
print(f'CUDA: {torch.cuda.is_available()}')
print(f'GPU: {torch.cuda.get_device_name(0)}')
\""
```

预期输出：

```
PyTorch 版本  : 2.x.x+cu126
CUDA 可用     : True
CUDA 版本     : 12.6
GPU 名称      : NVIDIA GeForce RTX 3060
GPU 显存      : 12.0 GB
NCCL 版本     : 2.x.x
```

> **说明**：pip 安装时可能自动选择了不同 CUDA 版本的 wheel（如 cu130），只要 `torch.cuda.is_available()` 为 `True` 就不影响使用。

### 6.4 环境激活的完整命令

后续所有需要激活环境的地方，统一使用：

```bash
source ~/miniconda3/etc/profile.d/conda.sh
conda activate /data/shared/envs/train
```

## 第七章：NCCL 网络配置

### 7.1 确认网卡名

```bash
ip a
# 找到内网网卡名，比如 enp4s0
```

### 7.2 设置 NCCL 环境变量（两台都做）

```bash
cat >> ~/.bashrc << 'EOF'

# ===== NCCL 分布式通信配置 =====
export NCCL_SOCKET_IFNAME=enp4s0       # ← 替换为你的网卡名
export NCCL_IB_DISABLE=1               # 没有 InfiniBand 就禁用
export NCCL_DEBUG=WARN                 # 调试时改为 INFO
```

## 第九章：高质量数据集工程

> **训练质量的上限由数据决定。** 模型再强、训练再久，喂进去脏数据，精度照样上不去。这一章是"高精度"的第一道闸门，务必认真做。

### 9.1 数据质量五原则

| 原则 | 说明 | 出问题会怎样 |
|------|------|-------------|
| **标注正确** | 框要贴合目标、类别不能错 | 直接污染梯度，模型学错 |
| **标注一致** | 同一类目标所有框风格一致 | 不一致让模型"无所适从" |
| **覆盖充分** | 各类别、各场景、各姿态都要有 | 长尾类别精度拉胯 |
| **划分干净** | train/val/test 互不重叠、不泄漏 | 验证集分数虚高 |
| **分布均衡** | 类别数量不过分悬殊 | 模型偏向多数类 |

### 9.5 数据质量自动审计脚本

```bash
cat > /data/shared/code/vision-train/audit_dataset.py << 'PYEOF'
#!/usr/bin/env python3
"""数据集质量审计：类别分布 / 越界标签 / 图片标签不匹配 / 空标注"""
from pathlib import Path
from collections import Counter
import sys

ROOT = Path(__file__).resolve().parent
IMG_EXTS = {'.jpg', '.jpeg', '.png', '.bmp', '.webp', '.tif', '.tiff'}

def parse_yolo_labels(p: Path):
    """返回 [(class_id, x, y, w, h), ...]，越界的单独记录"""
    boxes, bad = [], []
    for line in p.read_text().splitlines():
        parts = line.split()
        if not parts:
            continue
        try:
            vals = [float(x) for x in parts]
            if len(vals) < 5:
                bad.append((line, '字段不足5个'))
                continue
            cid, cx, cy, w, h = vals[0], vals[1], vals[2], vals[3], vals[4]
            if any(v < 0 or v > 1 for v in (cx, cy, w, h)):
                bad.append((line, '坐标越界'))
            else:
                boxes.append((int(cid), cx, cy, w, h))
        except ValueError:
            bad.append((line, '非法数字'))
    return boxes, bad

def audit(split: str):
    img_dir = ROOT / split / 'images'
    lbl_dir = ROOT / split / 'labels'
    imgs = sorted(p for p in img_dir.rglob('*') if p.suffix.lower() in IMG_EXTS)
    cls_counter = Counter()
    no_label = []      # 图片缺标签
    empty_label = []   # 标签文件为空
    bad_labels = []    # 标签越界/格式错
    orphan_labels = [] # 标签无对应图片
    cls_set = set()

    for img in imgs:
        lbl = lbl_dir / img.with_suffix('.txt').name
        if not lbl.exists():
            no_label.append(img.name)
            continue
        boxes, bad = parse_yolo_labels(lbl)
        if not boxes and not bad:
            empty_label.append(img.name)
        cls_counter.update(c for c, *_ in boxes)
        cls_set.update(c for c, *_ in boxes)
        bad_labels.extend((img.name, line, reason) for line, reason in bad)

    # 孤立标签
    for lbl in lbl_dir.rglob('*.txt'):
        img = img_dir / lbl.with_suffix('.jpg').name
        if not img.exists() and not (img_dir / lbl.with_suffix('.png').name).exists():
            orphan_labels.append(lbl.name)

    print(f"\n===== {split} 审计报告 =====")
    print(f"  图片总数       : {len(imgs)}")
    print(f"  图片缺标签     : {len(no_label)}")
    print(f"  空标签文件     : {len(empty_label)}")
    print(f"  坏标签(越界等) : {len(bad_labels)}")
    print(f"  孤立标签文件   : {len(orphan_labels)}")
    print(f"  类别数量       : {len(cls_set)}")
    print(f"  各类别实例分布 :")
    for cid in sorted(cls_counter):
        print(f"      class {cid:>3d}: {cls_counter[cid]:>6d} 个实例")
    return no_label, empty_label, bad_labels

if __name__ == '__main__':
    for split in ['train', 'valid', 'test']:
        if (ROOT / split / 'images').exists():
            audit(split)
PYEOF

# 运行审计
cd /data/shared/code/vision-train
source ~/miniconda3/etc/profile.d/conda.sh
conda activate /data/shared/envs/train
python3 audit_dataset.py
```

**审计要重点关注**：
- **图片缺标签 / 标签越界** → 会导致训练报错或目标学错，必须先修。
- **类别分布严重不均**（比如某类 5000 个、某类 50 个）→ 见 9.7 长尾处理。
- **空标签文件** → 是真实负样本就保留，是漏标就补标。

### 9.6 划分策略：避免数据泄漏

数据泄漏是最隐蔽、最致命的精度杀手——验证集分数虚高，上线后精度崩塌。

```bash
# 推荐做法：按「场景/序列」分组划分，而不是按单张图随机划分。
# 如果 100 张图来自同一段视频的连续帧，随机划分会让 train 和 val 高度相似，
# 验证集等于"开卷考试"，mAP 虚高 3-10 个点。

# 简单可用的划分原则：
# 1. 先按场景/视频/采集批次分组
# 2. 再按组随机划分 train/valid/test（比如 8:1:1）
# 3. 保证同一组的图片只落在一个 split 里
```

### 9.7 长尾类别处理

当类别分布严重不均时，按优先级处理：

| 方法 | 说明 | 优先级 |
|------|------|--------|
| 补数据 | 为少数类多采集、多标注 | 最高（治本） |
| 数据增强 | 对少数类图片额外做几何/色彩增强 | 高 |
| 过采样 | 少数类图片在训练时重复采样 | 中 |
| 类别权重 | 提高少数类 loss 权重 | 中（治标） |
| 忽略 | 若少数类实例 < 20，考虑合并或删除该类 | 视业务 |

> YOLO 本身不支持按类别过采样，长尾问题应优先从数据层面解决（补数据 / 增强）。

### 9.8 数据增强策略（高精度关键）

Ultralytics 内置的增强超参数在 `hyp` 配置文件里（默认 `cfg/hyp/default.yaml`），核心几个：

| 增强 | 默认值 | 作用 | 高精度建议 |
|------|--------|------|-----------|
| `mosaic` | 1.0 | 四图拼接，大幅提升小目标 | 保持 1.0，最后 40 轮关闭 |
| `mixup` | 0.0 | 两图混合，提升泛化 | 0.1~0.3（类别均衡时可用） |
| `copy_paste` | 0.0 | 目标复制粘贴，极度提升小目标 | 0.1~0.3（小目标场景） |
| `degrees` | 0.0 | 随机旋转 | 10~20（旋转不变场景） |
| `translate` | 0.1 | 随机平移 | 保持 |
| `scale` | 0.5 | 随机缩放 | 保持 |
| `fliplr` | 0.5 | 水平翻转 | 保持（文字类要关） |
| `hsv_h/s/v` | 0.015/0.7/0.4 | 色彩抖动 | 保持 |

> **重要**：`close_mosaic`（最后 N 轮关闭 mosaic）对精度提升非常明显，脚本里默认已设 `CLOSE_MOSAIC=40`，不要关。

## 第十章：高精度训练脚本

### 10.1 训练参数规划

开始写脚本前，先确定以下参数：

| 参数 | 建议值 | 说明 |
|------|--------|------|
| 模型 | yolov8m.pt 或 yolo11m.pt | 中等大小，适合 12GB 显存 |
| 图像尺寸 | 1024 | 越大越慢但精度越高 |
| Batch/卡 | 6 | RTX 3060 12GB 的安全值 |
| 全局 Batch | 6 × GPU 数量 | 自动计算 |
| 学习率 | 0.01 × GPU 数量 | 线性缩放规则 |
| Epoch | 按需设置 | 目标检测通常 300~600 |

### 10.2 高精度训练的核心技巧一览

在动手写脚本前，先理解"哪些参数直接影响精度"，脚本里都有对应开关：

| 技巧 | 作用 | 脚本开关 |
|------|------|---------|
| **AMP 混合精度** | 提速 1.5~2x，几乎不损失精度 | `AMP = True` |
| **EMA 指数移动平均** | 平滑权重，提升泛化，最终用 EMA 权重 | Ultralytics 默认开启 |
| **SyncBN 同步批归一化** | 分布式下跨卡同步 BN 统计，补回小 batch 精度损失 | `SYNC_BN = True` |
| **线性缩放学习率** | 大全局 batch 下按 GPU 数放大 lr | `LR0 = 0.01 * WORLD_SIZE` |
| **Warmup 预热** | 前期小 lr，避免大 lr 起步震荡 | `WARMUP_EPOCHS = 3` |
| **余弦退火** | 后期 lr 平滑下降，收敛到更优解 | `COS_LR = True` |
| **标签平滑** | 防止过拟合、提升校准 | `LABEL_SMOOTHING = 0.05` |
| **权重衰减** | L2 正则，抑制过拟合 | `WEIGHT_DECAY = 0.0005` |
| **关闭 Mosaic** | 最后 N 轮用真实分布，精度明显提升 | `CLOSE_MOSAIC = 40` |

```bash
    except Exception as e:

# ============================================================================
# 进度读取
# ============================================================================
def read_csv_epoch() -> int | None:
    if not RESULTS_CSV.exists(): return None
    try:
        with RESULTS_CSV.open("r", encoding="utf-8-sig") as f:
            reader = csv.DictReader(f)
            last = None
            for row in reader:
                for k, v in row.items():
                    if "epoch" in k.strip().lower() and v.strip():
                        try: last = int(float(v))
                        except: pass
            return last
    except: return None

def read_ckpt_epoch(ckpt: dict) -> int | None:
    epoch = ckpt.get("epoch")
    if epoch is None: return None
    try:
        e = int(epoch)
        return e + 1 if e >= 0 else None
    except: return None

def get_completed_epochs(ckpt: dict | None = None) -> int | None:
    candidates = []
    if ckpt is not None:
        ce = read_ckpt_epoch(ckpt)
        if ce is not None: candidates.append(ce)
    csv_e = read_csv_epoch()
    if csv_e is not None: candidates.append(csv_e)
    return max(candidates) if candidates else None

# 检查训练状态
# ============================================================================
def check_training_status() -> tuple[str, dict | None]:
    section("检查训练状态")
    log(f"  last.pt: {LAST_PT}  {'存在' if LAST_PT.exists() else '不存在'}")
    log(f"  best.pt: {BEST_PT}  {'存在' if BEST_PT.exists() else '不存在'}")

    if not LAST_PT.exists():
        log("  → 首次训练")
        return "new", None

    ckpt = load_ckpt(LAST_PT)
    if not isinstance(ckpt, dict):
        log("  ⚠ last.pt 格式异常")
        return "new", None

    completed = get_completed_epochs(ckpt)
    has_opt = ckpt.get("optimizer") is not None

    log(f"  epoch: {ckpt.get('epoch')}, 已完成: {completed}, optimizer: {'有' if has_opt else '无'}")

    if completed is not None and completed >= TARGET_EPOCHS:
        log("  → 训练已完成")
        return "done", ckpt

    if has_opt and completed is not None and completed > 0:
        log(f"  → 断点续训 (从 epoch {completed})")
        return "resume", ckpt

    log("  ⚠ 无 optimizer，从权重重新开始")
    return "new", ckpt


# ============================================================================
# 准备续训 checkpoint
# ============================================================================
def prepare_resume_checkpoint(ckpt: dict) -> Path:
    patched = dict(ckpt)
    train_args = dict(as_dict(ckpt.get("train_args", {})))
    old_epochs = train_args.get("epochs", "?")
    train_args["epochs"] = TARGET_EPOCHS
    train_args["data"] = str(DATA_YAML)
    train_args["patience"] = PATIENCE
    patched["train_args"] = train_args

    for key in ("ema", "model"):
        obj = patched.get(key)
        if obj is not None and hasattr(obj, "args"):
            try:
                m_args = dict(as_dict(obj.args))
                m_args["epochs"] = TARGET_EPOCHS
                m_args["data"] = str(DATA_YAML)
                obj.args = m_args
            except: pass

    atomic_save(patched, RESUME_PT)
    completed = get_completed_epochs(ckpt)
    log(f"  原 epochs: {old_epochs} → 新 epochs: {TARGET_EPOCHS}")
    log(f"  已完成: {completed}, 剩余: {TARGET_EPOCHS - (completed or 0)}")

    if WORLD_SIZE > 1 and dist.is_initialized():
        dist.barrier()
    return RESUME_PT
```

## 第十二章：训练质量监控与评估

> 训练"跑起来"只是及格，"训练质量好不好"要看指标曲线。这一章教你读懂训练过程，及时发现问题。

### 12.1 核心评估指标

| 指标 | 含义 | 关注点 |
|------|------|--------|
| **Precision（精确率）** | 预测出的目标里有多少是真的 | 误报多 → 偏低 |
| **Recall（召回率）** | 真实目标里有多少被找出来 | 漏检多 → 偏低 |
| **mAP50** | IoU=0.5 下的平均精度 | 主要对标指标 |
| **mAP50-95** | IoU 0.5~0.95 的平均精度 | 更严格，反映定位精度 |
| **各类别 AP** | 单类别精度 | 定位长尾/难类别 |

### 12.2 训练过程监控：看懂 loss 曲线

```
loss
 │
 │  ╭─╮
 │ ╱  ╲___train_loss___╮
 │╱                     ╲________
 │                               ╲
 │   ╭─╮
 │  ╱  ╲________val_loss___________╱  ← 开始回升 = 过拟合
 │ ╱
 └──────────────────────────────► epoch
```

| 现象 | 诊断 | 对策 |
|------|------|------|
| train loss 下降，val loss 也降 | 正常，继续训 | — |
| val loss 开始回升（拐点后） | **过拟合** | 增大 weight_decay、加 label_smoothing、加数据增强、减小模型 |
| train loss 一直不降 | **欠拟合 / lr 不对** | 提高 lr、加大模型、检查数据 |
| loss 震荡剧烈 | lr 太大 | 降低 lr0 |

## 第十三章：提升精度的调优路线图

> 精度上不去时，别瞎调参数。按下面**从数据到模型到训练策略**的顺序排查，每一步都有明确收益。

### 13.1 调优方法论：先小规模快速迭代

```
完整数据集 + 双机全epoch 训练一次要几个小时，盲目调参 = 浪费算力。

正确姿势：
1. 用 20% 数据 + 少量 epoch（如 20），快速跑通，验证「改动能生效」
2. 锁定方向后，再上完整数据 + 完整 epoch
3. 每次只改一个变量，才能归因「精度提升来自哪里」
```

### 13.2 提升精度清单（按优先级从高到低）

| 优先级 | 手段 | 预期收益 | 成本 |
|--------|------|---------|------|
| ⭐⭐⭐ | 补数据 / 修标注 / 均衡类别 | 最大，几个到十几个点 | 高（人工） |
| ⭐⭐⭐ | 更大输入尺寸 imgsz 640→1024 | 2~5 个点 | 显存/时间 |
| ⭐⭐⭐ | 更大模型 n→s→m→l→x | 2~5 个点 | 显存/时间 |
| ⭐⭐ | close_mosaic 最后 40 轮关闭 | 1~3 个点 | 无 |
| ⭐⭐ | 标签平滑 0.05 | 0.5~2 个点 | 无 |
| ⭐⭐ | 余弦退火 + 更长 epoch | 1~3 个点 | 时间 |
| ⭐⭐ | mixup / copy_paste（小目标） | 1~3 个点 | 无 |
| ⭐ | SyncBN（分布式） | 0.5~2 个点 | 无 |
| ⭐ | TTA 测试时增强 | 1~2 个点 | 仅推理变慢 |

### 13.3 常见精度问题诊断表

| 现象 | 最可能原因 | 优先排查 |
|------|-----------|---------|
| 小目标精度极差 | 分辨率不够 / 数据少 | imgsz 调大、加 copy_paste |
| 某类精度极差 | 该类数据少或标注差 | 补数据、查标注 |
| 两类别互相混淆 | 类别区分度低 | 补区分性样本 |
| 验证集分数虚高 | 数据泄漏 | 按 9.6 重新划分 |
| 双机精度比单机低 | 大 batch 没补偿 / BN 没同步 | 线性缩放 LR + SyncBN |
| 训练后期 mAP 掉 | 过拟合 | 加正则 / 早停 |

## 第十五章：踩坑记录与解决方案

### 问题 1：`'rank' is not a valid YOLO argument`

**错误信息**：

```
SyntaxError: 'rank' is not a valid YOLO argument.
'world_size' is not a valid YOLO argument.
```

**原因**：Ultralytics 8.4.x 不再接受 `rank` 和 `world_size` 作为 `model.train()` 参数。

**解决**：从 `model.train()` 调用中删除这两个参数，Ultralytics 通过环境变量 `RANK` 和 `WORLD_SIZE` 自动获取。

### 问题 2：`Default process group has not been initialized`

**错误信息**：

```
ValueError: Default process group has not been initialized,
please make sure to call init_process_group.
```

**原因**：Ultralytics 看到 `RANK` 和 `LOCAL_RANK` 环境变量就认为是分布式模式，内部会调用 `DistributedSampler`，但不会自动初始化 NCCL 进程组。

**解决**：在脚本最开始（`model.train()` 之前）手动初始化：

```python
import torch.distributed as dist

if not dist.is_initialized():
    dist.init_process_group(backend="nccl", init_method="env://")
torch.cuda.set_device(LOCAL_RANK)
```

### 问题 3：`total_mem` AttributeError

**错误信息**：

```
AttributeError: 'torch._C._CudaDeviceProperties' object has no attribute 'total_mem'.
Did you mean: 'total_memory'?
```

**原因**：新版 PyTorch 把 `total_mem` 改名为 `total_memory`。

**解决**：

```bash
sed -i 's/\.total_mem/\.total_memory/g' train_yolo_distributed.py
```

### 问题 4：`torchaudio` 安装失败

**错误信息**：

```
ERROR: Could not find a version that satisfies the requirement torchaudio
```

**原因**：`torchaudio` 可能没有对应 CUDA 版本的预编译 wheel。

**解决**：做视觉训练不需要 `torchaudio`，直接跳过，只装 `torch` 和 `torchvision`。

### 问题 5：node2 找不到 PyTorch

**错误信息**：

```
ModuleNotFoundError: No module named 'torch'
```

**原因**：conda 环境装在了 node1 本地路径，node2 看不到。

**解决**：将 conda 环境装到 NFS 共享路径 `/data/shared/envs/train`。

### 问题 6：torchrun 吞掉错误信息

**现象**：torchrun 只显示 `exitcode: 1`，看不到 Python traceback。

**解决**：用单机模式直接运行，能看到完整报错：

```bash
WORLD_SIZE=1 RANK=0 LOCAL_RANK=0 MASTER_ADDR=node1 MASTER_PORT=29600 \
  python3 train_yolo_distributed.py 2>&1 | head -100
```

### 问题 7：训练卡在初始化不跑

**原因**：两台没同时启动，torchrun 在等待所有节点就绪。

**解决**：确保所有节点的 torchrun 命令都在执行，检查 `MASTER_ADDR` 和 `MASTER_PORT` 是否正确。

### 问题 8：训练速度两台比一台还慢

**原因**：千兆网带宽不够，AllReduce 通信成为瓶颈。

**解决**：
- 短期：调大 batch size，减少通信频率
- 长期：升级万兆网卡 + 万兆交换机

### 问题 9：CUDA OOM（显存不足）

**错误信息**：

```
RuntimeError: CUDA out of memory
```

**解决**（按优先级尝试）：

1. 减小 batch size：`BATCH = 6` → `4` → `2`
2. 减小图像尺寸：`IMGSZ = 1024` → `640`
3. 减小模型：`yolo11m.pt` → `yolo11s.pt` → `yolo11n.pt`

### 问题 10：`Address already in use`

**原因**：端口 29600 被占用。

**解决**：换一个端口：

```bash
# 在 torchrun 命令中修改
--rdzv_endpoint=node1:29501
```

同时修改 `~/.bashrc` 中的 `MASTER_PORT`。

### 问题 11：NCCL WARN lib wrapper not initialized

**日志**：

```
NCCL WARN lib wrapper not initialized.
```

**说明**：这是关于 InfiniBand 的警告，不影响 TCP 通信。因为我们设置了 `NCCL_IB_DISABLE=1`，NCCL 会走 TCP/socket 通信，完全正常。可以忽略。

### 问题 12：分布式精度低于单机

**现象**：多卡训练出的模型 mAP 反而比单卡低 1~3 个点。

**原因**：大全局 batch 下 BN 统计不准 + 学习率没跟上。

**解决**：
1. 确认 `LR0 = 0.01 * WORLD_SIZE` 线性缩放已生效
2. 开启 `SYNC_BN = True` 同步 BN 统计
3. 若还偏低，适当降低 `LR0`（如 `0.008 * WORLD_SIZE`）并延长 epoch

### 问题汇总表

| 序号 | 错误信息 | 根本原因 | 解决方法 |
|------|---------|---------|---------|
| 1 | `'rank' is not a valid YOLO argument` | Ultralytics 8.4.x 不接受此参数 | 从 model.train() 中删除 |
| 2 | `Default process group has not been initialized` | 没有手动初始化 NCCL | 在 model.train() 之前调用 init_process_group |
| 3 | `'total_mem' attribute does not exist` | PyTorch 改名了 | 改用 `total_memory` |
| 4 | `No matching distribution for torchaudio` | 没有对应 CUDA 版本的 wheel | 跳过 torchaudio |
| 5 | `No module named 'torch'` | conda 环境在本地路径 | 装到 NFS 共享路径 |
| 6 | torchrun 无详细错误 | torchrun 吞掉了 traceback | 用单机模式直接运行 python3 |
| 7 | 训练卡住不动 | 没有同时启动所有节点 | 确保所有节点同时运行 |
| 8 | 双机比单机慢 | 网络带宽不够 | 升级万兆网 |
| 9 | CUDA OOM | 显存不足 | 减小 batch/imgsz/模型 |
| 10 | Address already in use | 端口冲突 | 换端口 |
| 11 | NCCL WARN lib wrapper | 无 InfiniBand 的正常警告 | 忽略 |
| 12 | 分布式精度低于单机 | 大 batch + BN 未同步 | 线性缩放 LR + SyncBN |

## 附录：原理说明

### A.1 DDP（Distributed Data Parallel）原理

```
┌────────────────────────────────────────────────────────┐
│                       DDP                               │
│                                                         │
│  GPU 0          GPU 1          GPU N                    │
│  ┌────────┐    ┌────────┐    ┌────────┐                │
│  │模型参数│    │模型参数│    │模型参数│  ← 每卡完整副本 │
│  │优化器  │    │优化器  │    │优化器  │  ← 每卡完整副本 │
│  │梯度    │    │梯度    │    │梯度    │  ← 每卡完整副本 │
│  └────────┘    └────────┘    └────────┘                │
│                                                         │
│  1. DistributedSampler 把数据均分到各卡                  │
│  2. 每卡独立做前向传播 + 反向传播                       │
│  3. AllReduce 同步梯度（取平均）                        │
│  4. 每卡用相同梯度更新参数                              │
│  → 训练结束后，所有卡的模型完全一致                     │
└────────────────────────────────────────────────────────┘
```

### A.2 为什么大 Batch 会损害精度（以及如何补偿）

```
多卡 = 更大的全局 Batch = 更快的训练，但是：

大 Batch 的两个精度副作用：
├── BN 统计不准：每卡 batch 只有 6，统计方差大
│     └── 补偿：SyncBN 跨卡同步统计
│
└── 优化器步长大：梯度平均后更"平滑"，但更新次数变少
      └── 补偿：线性缩放 LR（lr = 0.01 × GPU数）+ 余弦退火
```

### A.3 高精度训练技巧原理

| 技巧 | 原理 |
|------|------|
| **AMP** | 前向用 FP16 提速、关键运算保 FP32，几乎不损精度 |
| **EMA** | 权重做指数滑动平均，最终模型更平滑、泛化更好 |
| **SyncBN** | 跨卡同步 BatchNorm 统计量，修小 batch 的统计偏差 |
| **标签平滑** | 把 one-hot 标签变成软标签，抑制过拟合 |
| **余弦退火** | LR 平滑降到接近 0，收敛到更优的平坦区域 |
| **Warmup** | 前期小 LR 平稳起步，避免大 LR 初期震荡破坏预训练权重 |
| **Close Mosaic** | 最后 N 轮用原始分布，让模型适应真实数据分布 |

### A.4 RTX 3060 12GB 显存预算

| 用途 | 占用 |
|------|------|
| YOLO11m 模型参数 | ~2 GB |
| 优化器状态 (SGD) | ~2 GB |
| 梯度 | ~2 GB |
| 激活值缓存 (batch=6, 1024px) | ~4-5 GB |
| 临时缓冲 | ~1 GB |
| **总计** | **~11-12 GB** |

> 如果出现 CUDA OOM，减小 `BATCH`（6→4→2）或 `IMGSZ`（1024→640）。

### A.5 torchrun 参数说明

```bash
torchrun \
  --nnodes=2              # 总节点数
  --nproc_per_node=1      # 每节点的 GPU 数
  --rdzv_id=yolo_train    # rendezvous ID（所有节点必须相同）
  --rdzv_backend=c10d     # rendezvous 后端
  --rdzv_endpoint=node1:29600  # Master 节点地址和端口
  train_yolo_distributed.py
```

| 参数 | 说明 |
|------|------|
| `--nnodes` | 参与训练的机器总数 |
| `--nproc_per_node` | 每台机器启动几个训练进程（通常 = GPU 数量） |
| `--rdzv_id` | 训练任务的唯一标识，所有节点必须相同 |
| `--rdzv_backend` | 使用 c10d 后端（PyTorch 内置） |
| `--rdzv_endpoint` | Master 节点的 IP:PORT |

### A.6 关键环境变量

| 变量 | 说明 | torchrun 自动设置？ |
|------|------|---------------------|
| `RANK` | 全局排名（0 到 WORLD_SIZE-1） | ✅ |
| `LOCAL_RANK` | 本机排名（0 到 nproc_per_node-1） | ✅ |
| `WORLD_SIZE` | 总进程数 | ✅ |
| `MASTER_ADDR` | Master 节点地址 | ✅（从 rdzv_endpoint） |
| `MASTER_PORT` | Master 节点端口 | ✅（从 rdzv_endpoint） |
| `NCCL_SOCKET_IFNAME` | NCCL 使用的网卡 | ❌ 手动设置 |
| `NCCL_IB_DISABLE` | 禁用 InfiniBand | ❌ 手动设置 |
